# ТЗ для GigaCode: редизайн интерфейса Product Owner Workspace

## 1. Цель

Переработать текущий интерфейс локального Task Tracker, чтобы он:

- визуально соответствовал стилю корпоративного AS21 / WORKS;
- выглядел как полноценное рабочее пространство владельца продукта;
- был компактнее и удобнее для ежедневной работы;
- не показывал форму создания локальной задачи постоянно;
- позволял быстро фильтровать, синхронизировать и просматривать задачи;
- сохранял все существующие функции и данные.

## 2. Название продукта

Основное рекомендуемое название:

# **PO Workspace**

Подзаголовок:

> Пространство владельца продукта DB

Альтернативы:

1. **PO Control Center**
2. **DB Product Space**
3. **Product Owner Hub**
4. **PO Command Center**
5. **DB Product Workspace**

Для текущей версии использовать:

```text
PO Workspace
Пространство владельца продукта DB
```

## 3. Визуальный стиль

Интерфейс должен быть выполнен в стиле AS21 / WORKS по предоставленным скриншотам:

- светлый нейтральный фон;
- белые рабочие панели;
- темный основной текст;
- мягкие серо-голубые разделители;
- синие акценты;
- спокойные зеленые статусы завершения;
- компактные отступы;
- скругленные кнопки и карточки;
- современный sans-serif шрифт.

Не оставлять:

- стандартные браузерные стили;
- serif-шрифт;
- неоформленные HTML-поля;
- длинные тексты без ограничения;
- постоянно раскрытую форму создания задачи;
- чрезмерно яркие цвета.

## 8. Боковая навигация

Пункты:

1. Обзор
2. Задачи
3. Спринты
4. Релизы
5. Команда
6. Аналитика
7. Настройки

На первом этапе реально работающими могут быть только Обзор, Задачи и Команда. Остальные можно показать как `disabled` или «скоро».

Требования:

- активный пункт — светло-синий фон;
- hover — мягкий серо-голубой фон;
- иконка и подпись;
- ширина 220–250 px;
- возможность свернуть панель.

## 9. Верхняя панель

Слева:

```text
Задачи
Задачи AS21 и локальные задачи владельца продукта
```

Справа:

1. `+ Создать задачу`
2. `Синхронизировать`
3. иконка обновления;
4. иконка настроек;
5. при необходимости аватар.

Главная кнопка:

```text
+ Создать задачу
```

## 10. Создание локальной задачи

Сейчас форма постоянно занимает верх страницы. Это необходимо убрать.

Новое поведение:

- форма открывается только по кнопке `+ Создать задачу`;
- предпочтительно использовать правый drawer;
- допустима модальная форма.

Поля:

- Название;
- Описание;
- Исполнитель;
- Статус;
- Спринт;
- Продукт;
- Приоритет;
- Source URL;
- Теги;
- Дата завершения;
- признак `Локальная задача`.

Кнопки:

- Создать;
- Отмена.

UX:

- закрытие по Escape;
- предупреждение при несохраненных данных;
- обязательное поле «Название»;
- уведомление об успешном создании;
- новая карточка сразу появляется в списке;
- фокус в поле «Название».

## 11. Фильтры

Компактная панель над задачами:

- статус — multi-select;
- исполнитель;
- продукт;
- спринт;
- источник: AS21 / Local;
- приоритет;
- текстовый поиск;
- кнопка `Сбросить`.

Не использовать стандартные браузерные select. Активные фильтры показывать chips.

При синхронизации:

- spinner;
- блокировка повторного нажатия;
- итог: добавлено / обновлено / без изменений / ошибки.

## 12. Карточки задач

Карточка должна содержать:

- источник;
- продукт;
- код;
- название;
- краткое описание;
- статус;
- исполнитель;
- спринт;
- дату создания или обновления;
- Source URL;
- действия.

Пример:

```text
[AS21] [OLP] [QA]

CRPV-51910
Product Feature: Хранение данных K-2

Краткое описание задачи...

Исполнитель: Виктор Калачанов
Спринт: OLP-SPRINT-3
Обновлено: 03.08.2026

[Открыть в AS21] [Подробнее] [...]
```

Описание ограничить 3–4 строками и добавить `Показать полностью`.

## 13. Статусы

Использовать:

```text
knowledge/process/S21_WORKFLOW_STATUSES.md
config/workflow_statuses.yaml
```

Показывать компактными badges. Не менять бизнес-смысл статусов.

## 14. Подробности задачи

По `Подробнее` открывать drawer или отдельную страницу:

1. заголовок и код;
2. статус;
3. описание;
4. исполнитель;
5. спринт;
6. продукт;
7. приоритет;
8. Source URL;
9. история синхронизации;
10. локальные комментарии;
11. действия.

Для AS21-задачи должна быть кнопка `Открыть в AS21`.

## 15. Пустые и служебные состояния

Нет задач:

```text
Задачи не найдены
Измените фильтры или синхронизируйте данные с AS21.
```

Ошибка:

```text
Не удалось получить задачи из AS21.
Проверьте подключение и повторите попытку.
```

Во время загрузки использовать skeleton-карточки.

## 16. Адаптивность

- desktop от 1280 px;
- sidebar сворачивается;
- фильтры переносятся;
- drawer не выходит за экран;
- карточки не создают горизонтальный scroll.

## 17. Технические требования

Перед изменениями:

1. определить frontend stack;
2. не переписывать приложение без необходимости;
3. сохранить API-контракты;
4. не менять схему БД без миграции;
5. вынести theme в CSS variables;
6. разбить UI на компоненты;
7. сохранить работающую синхронизацию AS21.

## 18. AS21 и локальные задачи

### AS21

- импортируются и синхронизируются;
- имеют Source URL;
- AS21 остается источником истины;
- локальное приложение не должно незаметно перезаписывать исходные поля.

### Local

- создаются по кнопке;
- хранятся локально;
- имеют `source = local`;
- могут не иметь Source URL;
- используются как задачи или напоминания PO.

Источник обязательно отображать в карточке.

## 20. Критерии приемки

1. Интерфейс визуально близок к AS21 / WORKS.
2. Используется sans-serif шрифт.
3. Добавлены WORKS, DB Tribe и `PO Workspace`.
4. Есть боковая навигация.
5. Постоянная форма создания удалена.
6. Форма открывается по кнопке.
7. Старые задачи отображаются.
8. Синхронизация работает.
9. Статусы показаны badges.
10. Длинные описания свернуты.
11. AS21 и Local визуально различаются.
12. Desktop-версия работает корректно.
13. Нет неоформленных стандартных HTML-компонентов.
14. Данные не потеряны.
15. Новые компоненты имеют базовые тесты.
