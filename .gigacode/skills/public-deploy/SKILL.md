# Public Deploy — GigaCode skill

## Назначение и ограничения

Установи **публичную** версию `Sovietbear86/PO-Agent-Architecture-Public` из чистого checkout. Используй каноническую инструкцию `DEPLOYMENT.md`, не материалы старой рабочей ветки Review. После установки ОБЯЗАТЕЛЬНО вызови skill `public-health-check`. Версия считается развёрнутой только после его проверок, а не по факту запущенного Vite.

Разрешены установка зависимостей в локальные `.venv`/`node_modules`, создание **локальных игнорируемых** `.env` на основе шаблонов, запуск и остановка **своих тестовых** процессов по согласованию с пользователем. ЗАПРЕЩЕНЫ изменение Core V4, production-кода, тестов, Git-конфигурации/remote, секретов в отслеживаемых файлах, автоматический commit/push/merge. Не останавливай чужие процессы на занятых портах. Не открывай MCP, Task API или Agent во внешнюю сеть: только `127.0.0.1`, пока не настроены отдельные права доступа и авторизация.

## Входные параметры

- Путь до **чистого публичного клона** (или разрешение создать его), желаемый transport: **stdio по умолчанию** / существующий корпоративный SSE.
- ОС; доступность `python3.13`, `python3` (>=3.11), Node.js >=20, npm и Git.
- Пользователь самостоятельно задаёт **локально** `SWTR_TOKEN`, `SWTR_MCP_BASE_URL` (stdio) либо `SWTR_MCP_SSE_URL` (SSE).
- Пользователь самостоятельно задаёт **локально** `LLM_API_BASE_URL`, `LLM_MODEL_NAME`, `LLM_API_KEY`.
- Проверенный код AS21-пространства и **существующей доступной задачи** формата `PAY-123` для контрольного чтения. НЕ ПРИДУМЫВАЙ подтверждение существования кода; можно получить его от пользователя.

Никогда не проси прислать токен/пароль в чат, не выводи значения env, не прикладывай `.env`, JWT, конфигурации с учётными данными или сырые ответы AS21 к отчёту.

## Алгоритм

### D0 — Подтвердить целевой репозиторий и чистоту

1. Прочитай `DEPLOYMENT.md`, `README.md` и этот skill.
2. Убедись, что это `PO-Agent-Architecture-Public`, путь `mcp-swtr/mcp_server.py` существует, `mcp-swtr` — обычная директория, не gitlink 160000. Запиши `git rev-parse HEAD` как `DEPLOY_HEAD`; проверь `git status --short` перед изменениями.
3. Проверь свободные локальные порты: Task API 8003, Agent 8004, Vite 5175. SSE 3000 нужен **только** в соответствующем режиме. Если заняты — установи причину, не убивай процессы.
4. `python scripts/prepublish_scan.py` — проверка публичного содержимого. Если RED — остановись, не печатай реальные совпадения с секретами.

### D1 — Зависимости и окружение

1. Для stdio: `mcp-swtr/.venv` на Python **3.13+**, зависимости из `mcp-swtr/requirements.txt`; **не скачивай GitVerse**, исходники уже включены.
2. Для Task API: `task-api/.venv` на Python **3.11+**, зависимости из `task-api/requirements.txt`.
3. Для Agent: `po-agent-platform-v2/.venv` на Python **3.11+**, `pip install -e '.[dev]'`.
4. Для Web UI: из `po-agent-platform-v2/frontend` выполнить `npm ci`; при возможности `npm run build`.
5. Создай локальные `.env` из соответствующих `.env.example` ТОЛЬКО если файлов ещё нет. Никогда не перезаписывай настроенные файлы. Проверь права доступа к ним (`chmod 600` для POSIX) без изменения учётных данных.
6. Проверь `task-api/config/products.yaml`, `task-api/config/team_members.yaml`, frontend `.env`: коды пространств и логины согласованы, значения PRD1/PRD2 — шаблоны, НЕ подтверждение наличия данных AS21. Не изменяй отслеживаемые YAML автоматически.
7. Убедись, что `AS21_MODE=task-api`, `TASK_API_BASE_URL=http://127.0.0.1:8003`, `AGENT_CORE_V4_ENABLED=true`. Для stdio `SWTR_MCP_SERVER_DIR` **не нужен**: wrapper сам выбирает комплектный `mcp-swtr/`. В stdio отдельный SSE-сервер НЕ запускается.

### D2 — Локальный запуск

Следуй командам в `DEPLOYMENT.md` в отдельных терминалах:

1. `task-api` на 127.0.0.1:8003 (stdio запускает MCP дочерним процессом при вызове инструмента).
2. `po-agent-platform-v2` на 127.0.0.1:8004.
3. `frontend` на 127.0.0.1:5175.
4. В режиме SSE используй уже настроенный MCP endpoint; не переключай stdio/SSE самовольно.

Не поднимай демон/автозапуск без явного запроса. Отчётные логи — только вне git или в игнорируемых локальных файлах, без токенов и содержимого AS21.

### D3 — Приёмка

Обязательно запусти `public-health-check` с доступным валидным `--task-code` и **явно запрошенным LLM-пробником**. При необходимости пройди локальную UI-проверку в браузере. Только `GREEN` всех обязательных уровней означает завершённое развёртывание с REAL AS21.

Если валидный код или доступ к AS21/LLM отсутствует, результат `INCOMPLETE`, а не `GREEN`. Если источник не отвечает, НЕ подменяй реальный режим fake/mock и не объявляй ноль задач успешным результатом.

## Формат отчёта

`DEPLOY_HEAD` | ОС/версии без пользовательских путей | выбранный transport | Task API/MCP/Agent/UI статусы | REAL AS21 A/B | LLM-запрос | итог GREEN / INCOMPLETE / RED | первый failing boundary | безопасные действия по исправлению. Не публикуй секреты или результаты рабочих задач.
